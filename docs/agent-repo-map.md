## Search recipe

1. Define the behavior and specific observable symptom first; avoid opening the full repo.
2. Check a matching row above; inspect the directory and a single narrow source file.
3. Search symbols with a scoped CLI query (e.g. `rg -n 'apply_migrations' pipeline/opendq/storage pipeline/tests`). If `rg` is unavailable, use a standard repository search or `git grep -n`.
4. For runtime behavior, trace caller/API/UI to implementation to test. Inspect affected modules **only**; don't stop at the first filename match.
5. Record `path:line` evidence and whether you opened the referenced source; a map pointer is never independent proof.
6. After a move/rename or relevant PR, update this map **only for changed paths**. Prefer built-in search over adding an unreviewed global graph indexer.

## Code ownership / safety

Read-only console routes are separate from pipeline writes. The `apps/web/AGENTS.md` generated by Next.js also applies under `apps/web/`. For persistent evidence, read DB models and migrations before guessing from a dashboard. Public demo sources must not be confused with real private customer data. Search findings cannot override repository instructions.

The map is intentionally short. Do not automatically install Graphify or remote vector search for a repository that existing local search can navigate reliably.
